# 08 · 自己算 PE/PB：用原料，不抄结论

> 大多数人算估值是抄一个 PE 数字。抄来的数字有三个问题：**口径不明**（静态/TTM/动态？总市值/自由流通/等权？）、**时点不明**（哪天收盘？）、**来源不明**（谁算的、怎么算的）。
> 这一页把 PE/PB 拆回小学算术：**总市值 ÷ 净利润**、**总市值 ÷ 净资产**。原料自己取，结论自己算，算完再跟公开数字对账。

对应脚本：`scripts/rawdata.py`（`fetch` 取原料 / `calc` 算并核对）

---

## 一、书的原话就是这两个公式

| 指标 | 公式 | 书里的位置 |
|---|---|---|
| 市盈率 PE | 市值 ÷ 盈利（每股价格 ÷ 每股盈利） | 第 4 章「市盈率」 |
| 市净率 PB | 市值 ÷ 净资产（每股价格 ÷ 每股净资产） | 第 4 章「市净率」 |
| 盈利收益率 | 盈利 ÷ 市值 = 1 ÷ PE | 第 4 章「盈利收益率」 |
| 股息率 | 现金分红 ÷ 市值 | 第 4 章「股息率」 |

指数层面的版本把"每股"换成"整个指数"：

```
指数 PE = Σ(成分股总市值) ÷ Σ(成分股净利润)      ← 一个分数，分子分母都是加法
指数 PB = Σ(成分股总市值) ÷ Σ(成分股净资产)
```

就这么两行。难点从来不是算术，而是**把成分股名单、净利润、净资产、市值取全**。

---

## 二、四个原料，四个来源

| 原料 | 从哪来 | 说明 |
|---|---|---|
| 成分股名单 | 东方财富数据中心 `RPT_INDEX_COMPONENT` | 一次拉全 300 只，索引代码如 `000300` |
| 收盘价 / 总市值 / 流通市值 | 腾讯行情 `qt.gtimg.cn`（60 只一批） | 字段 39=PE(TTM)、44=流通市值、45=总市值、46=PB，**后两个用来算，PE/PB 只用来对账** |
| 净利润（累计） | 东方财富 `RPT_LICO_FN_CPD` | 取 `PARENT_NETPROFIT`（归母净利润）、`BPS`（每股净资产） |
| 净资产 | **BPS × 总股本**，总股本 = 总市值 ÷ 收盘价 | 不直接抄"净资产"字段，而是用两个原料相乘，可复算 |

净利润必须凑出 **TTM（滚动十二个月）**：

```
TTM 净利润 = 本期累计净利润 + 上年全年净利润 − 上年同期累计净利润
例：2026 中报 + 2025 年报 − 2025 中报 = 2025Q3~2026Q2 的十二个月
```

> 为什么不用"上年度净利润"（静态 PE）？因为财报一年只出四次，静态 PE 最长会滞后 12 个月。
> 为什么不用"预测净利润"（动态 PE）？因为那是别人的预测，不是数据。

## 三、一次完整运行

```bash
# 1) 取原料（会缓存到 ./_ifg_cache，重复跑不重复抓）
python rawdata.py fetch --index 000300

# 2) 自己算 + 逐只对账 + 导出明细 CSV
python rawdata.py calc --index 000300 --verify --csv 000300.csv --top 10 \
       --published-pe 12.9964 --published-pb 1.3781
```

输出长这样（2026-10-19 实跑）：

```
成分股 300 只 → 取到行情 300 只 → 进入合计 300 只（市值覆盖 100.00%；其中亏损 21 只）

原料合计（亿元）：
  总市值            654565.25
  自由流通市值       493753.86
  净利润 TTM          50090.22
  净资产             467267.06

自己算出来（不是抄的）：
  PE(中证口径)        13.07   = Σ总市值 / Σ净利润（亏损股的负利润计入；共 21 只亏损）
  PE(剔除亏损)        12.39   = 只把盈利公司加权，通常比中证口径低
  PE(自由流通加权)     9.86   = Σ自由流通市值 / Σ净利润（权重偏小盘）
  PE(个股中位数)      18.00   = 等权视角，不受巨头影响
  PB(总市值加权)       1.37   = Σ总市值 / Σ净资产
```

## 四、数值真实性：三个层次的证据

### 层一 · 逐只对账（最硬的一层）

我们算的**每一只**股票的 PE，去和行情软件公布的个股 PE 比。若两者吻合，说明"市值÷净利润"这条链是通的：

| 指数 | 对账只数 | 中位误差 | 误差 ≤1% 占比 |
|---|---|---|---|
| 沪深300 | 279 | **0.012%** | 97.5% |
| 上证50 | 49 | **0.013%** | 98.0% |

误差 >5% 的只有 6 只（沪深300），全部是**当年发生重组、换股、大额资产注入**的公司——TTM 相减法在这种公司身上必然失真（合并前后股本不同）。它们合计市值占指数不到 1.3%，对指数 PE 的影响小于 0.1 个点。

> 这就是"真实性"的实证：**279/300 只个股的 PE 与公开数据在小数点后两位一致**，不是靠一句"数据来自某某"取信。

### 层二 · 指数层对账（五个指数，2026-10-19）

| 指数 | 我们算的 PE | 公开 PE | 偏差 | 我们算的 PB | 公开 PB | 偏差 |
|---|---|---|---|---|---|---|
| 上证50 000016 | 10.87 | 10.78 | +0.84% | 1.237 | 1.239 | −0.15% |
| 沪深300 000300 | 13.06 | 13.00 | +0.51% | 1.370 | 1.378 | −0.56% |
| 中证红利 000922 | 9.13 | 9.01 | +1.43% | 0.896 | 0.889 | +0.69% |
| 中证500 000905 | 29.44 | 29.25 | +0.65% | 2.111 | 2.123 | −0.55% |
| 创业板指 399006 | 31.57 | 31.90 | −1.06% | 4.623 | 4.471 | +3.40% |

公开 PE 取蛋卷 `index_eva` 接口同年同日值。**5 个指数 PE 偏差全部在 1.5% 以内，PB 除创业板外都在 0.7% 以内。**

剩下的偏差来自三处，都可解释、都不是错误：

1. **加权方式**：中证官网用「调整市值」（自由流通比例分档加权），我们用总市值。两者对结果的影响见"PE(自由流通加权) 9.86 vs 总市值 13.07"——差别很大，说明加权方式本身就是一个必须交代的口径。
2. **PE 口径**：静态 / TTM / 动态能差 8%~15%（见 `02-catalog.md`）。
3. **净资产口径**：创业板 PB 偏 3.4%，多半是"归母净资产"与"全部股东权益"的差别（少数股东权益占比高的公司，两种算法差得多）。

### 层三 · 明细可抽查（任何人可复算）

`--csv` 导出每一只的原料与结果：

```csv
code,name,price,mcap_yi,float_mcap_yi,np_ttm_yi,bps,equity_yi,pe_ours,pb_ours,pe_vendor,pb_vendor,source,fetched_at
601398,工商银行,8.61,30686.6,...,3741.4,...,39623.2,8.20,0.77,8.20,0.77,...
```

随便挑一只，用计算器验：`30686.6 ÷ 3741.4 = 8.20`。**这就是"数值真实性"**——不需要信任谁，只需要会除法。

## 五、这套方法的边界（必须交代）

| 边界 | 后果 | 应对 |
|---|---|---|
| 只覆盖 A 股 | 恒生、H 股、纳斯达克、标普算不了 | 港股用公开 PE + 注明口径；或改用分位法 |
| 依赖免费接口 | 东财/腾讯改字段就断，且无 SLA | `--cache` 存原料，断了可复用旧原料；接口坏了就换（`fetch` 只负责取数，`calc` 独立可跑） |
| TTM 相减法在重组年份失真 | 个别股票误差可达 20%+ | `--verify` 会把误差 >5% 的列出来，占比大的要手工核对 |
| 亏损股处理 | 剔除亏损会让 PE 偏低 | 默认输出"中证口径"（负利润计入），另给"剔除亏损"作对照 |
| 缺财报的公司 | 无净利润 → 无法进合计 | 输出"真的缺数据的 N 只"及其市值占比，通常 <1% |
| 不是官方数据 | 不能作为法律、审计依据 | 与公开值对账后使用；偏差 >3% 就该怀疑数据本身 |

## 六、把算出来的数接进决策

`calc` 最后会直接打印下一步该敲的命令：

```
valuation.py signal --pe 13.0677 --pe-type ttm --method yield
```

注意三点：

1. **必须带 `--pe-type ttm`**。自己算的是 TTM，标成静态会误导后来的读者。
2. **PE 只是一把尺子**。盈利稳定的宽基用 `--method yield`；成长指数（创业板）要 `--method bog` 且必须给 `--percentile`；强周期（证券、能源）用 `--method pb`。方法选错，结论会从"买"翻到"卖"（见 `07-calibration.md` 5.2 节）。
3. **算出来的数要写进记录**。`dingtou.py record --valuation <你算的 PE> --valuation-type ttm`，以后回看才知道当时的判断依据是什么口径。

---

## 七、一句话总结

> PE、PB 不是"数据"，是**两个数相除的结果**。拿到分子分母，你就能自己算、自己验、自己解释偏差；
> 只拿到结果，你只能相信或怀疑，无法判断。
> 这一页的价值不在"算出 13.06"，而在**算出 13.06 的每一步都摊在桌面上**。

## 八、数据时间：谁在什么时候抓的（这一节决定结果可信度）

三段时间互不相同，混起来就会得出错误结论：

| 段 | 是什么 | 时间基准 |
|---|---|---|
| **行情** | 收盘价、总市值、流通市值 | 每次 `fetch` **现抓**，腾讯返回的 `quote_time` 精确到秒 |
| **财报** | 净利润、每股净资产 | 由**今天的日期**推出「最近一期已过披露截止日」的报告期 |
| **快照** | 阈值锚点（10Y 利率、债基收益） | 冻结在 `07-calibration.md` 里，2026-10-16 |

**报告期不是简单的"上一个季末"**。法定披露截止日是：一季报 4-30、中报 8-31、三季报 10-31、年报次年 4-30。

早期版本用「季末 + 35 天」推断，会在两个窗口出错：

| 窗口 | 错误后果 |
|---|---|
| 8-04 ~ 8-31（中报未披露完） | 只统计已披露公司 → Σ净利润偏小 → **PE 偏高** |
| 2-04 ~ 4-30（年报未披露完） | 同上，且年报期 TTM 就等于年报本身 → 误差最大 |

现在改为**按法定截止日判定**，并且在截止日前抓数据会被直接拒绝（`--allow-partial` 才放行）。

另外两条保护：

1. **`calc` 会报"这是 N 天前的快照"**，因为 `fetch` 之后你可能隔几天才跑 `calc`；
2. **财报缓存带元信息**（抓取时间 / 条数 / 是否已过截止日）。**没到截止日抓的半成品永远不会被缓存命中**，下次自动重抓——否则一次抓早就会永久污染之后所有计算。

> 时间戳怎么读：`rawdata.py calc` 表头会同时打印「抓取时间」「行情时间」「报告期披露截止」。
> 行情时间落在交易时段内 → 那是**盘中实时价**，PE 会随成交漂移；落在收盘后 → 才是当日收盘口径。要写报告，收盘后再跑。
