# 09 · 每日跟踪：关注清单 → 每日快照 → 投资判断 → 条件推算

对应脚本：`scripts/tracker.py`。这一份解决的是"**买了之后每天怎么办**"，前八份解决的是"该不该买"。

## 一、它替代了什么手工动作

没有跟踪器时，你每天要做四件重复劳动：

1. 打开两三个网站，把关注的七八只指数的 PE / 分位 / 股息率抄下来；
2. 回忆起阈值（买 10%？卖 3.0%？）再心算盈利收益率；
3. 判断"这只该买还是该等"，判断依据每天都可能记错；
4. 记录今天到底买了没有——大多数人这一步直接放弃，于是再也算不出真实年化。

跟踪器把 1~4 变成一条命令。更重要的副产品是**第 3 天之后你才有数据**：
面板值只能告诉你"别人算的历史分位"，自己攒的快照才能回答"这 30 天估值往哪走、我上次决定对不对"。

## 二、数据模型（三个文件，都在本地）

```
fund-track/
├── watchlist.json          关注清单（代码 / 名称 / 类型 / 挂的基金 / 目标仓位）
├── data/snapshots.csv      每日快照，一天一行 × 品种
└── reports/2026-10-20.md   每日日报（markdown）
```

`snapshots.csv` 的列固定为：

| 列 | 含义 |
|---|---|
| `date` | 快照日期（`--date` 可补录） |
| `key` | 品种代码（`000300` / `HSCEI` …） |
| `name` `kind` `type` | 名称、类别、四类型之一（决定用哪套估值法） |
| `close` | 指数点位（腾讯行情，失败留空） |
| `pe` `pb` | 市盈率 / 市净率 |
| `pe_pct` `pb_pct` | 历史分位（百分数，越低越便宜） |
| `dividend` `roe` | 股息率、净资产收益率（百分数） |
| `source` `fetched_at` | 数据来源与抓取时间戳 |

同一天重复 `collect` 会覆盖当天该品种的行，不会重复堆积。

`type` 是这份数据里唯一的判断题，取值：

| type | 含义 | 用的方法 |
|---|---|---|
| `value` | 盈利稳定的价值指数（宽基、红利、银行） | 盈利收益率法 |
| `grow` | 盈利高速成长（创业板、纳指） | 博格公式 + PE 分位 |
| `cycle` | 强周期、盈利不稳但不会长期亏损（证券、能源） | 博格变种 + PB 分位 |
| `skip` | 长期亏损、看不清 | 放弃 |

写错 `type` 的后果是整条判断错位：创业板 PE 31.6 用 `value` 会得出"卖出"，用 `grow` 才得出"分位 17% 处于低估区"。

## 三、四条命令

```bash
# 1. 一次性初始化（默认 7 只：沪深300/上证50/中证红利/中证500/创业板/H股/恒生）
python tracker.py init --dir ./fund-track

# 2. 改清单：代码:名称[:类型[:基金代码[:目标仓位]]]，多条用分号
python tracker.py watch --dir ./fund-track --add "000922:中证红利:value:100032:0.3"
python tracker.py watch --dir ./fund-track --remove 399006
python tracker.py watch --dir ./fund-track --list

# 3. 每天抓一次（约 3 秒/7 只）
python tracker.py collect --dir ./fund-track

# 4. 判断 + 分配 + 日报
python tracker.py analyze --dir ./fund-track --budget 2000 --base 1000
python tracker.py report  --dir ./fund-track --budget 2000
```

`--preset` 选阈值口径，默认 `cal`（2026 校准：买 10% / 卖 3.0%）；要看书中原值用 `--preset book`。

## 四、"是否投资"是怎么算出来的（不是拍脑袋）

每只品种依次过四道：

**① 方法分派**：`type` → `yield` / `bog` / `pb` / `skip`。分位法缺少分位数据时直接放弃判断，**不允许退回用绝对 PE 硬套**。

**② 阈值判定**（复用 `valuation.py`，与正文同一套数）：

- 盈利收益率 = 100 ÷ PE（港股再乘 0.9 折价；`--hk-exact` 按分红税精确算）
- 盈利收益率 > 买入线 → 分批投资；处于买入线与卖出线之间 → 坚定持有；< 卖出线 → 分批卖出
- 分位法（`grow` / `cycle`）：PE/PB 分位 < 30% → 低估区；30%~70% → 中位；> 70% → 高估区

**③ 打架处理**（这一条决定工具是帮手还是祸害）：

- 盈利率说买、分位却在 70% 以上（如中证红利 2026-10：盈利率 10.97%，分位 87%）→ 保留买入信号，但**仓位减半**并写明矛盾。理由是红利指数盈利稳定，绝对值优先；但历史高位意味着安全边际变薄。
- 分位说买、盈利率说卖（如创业板 2026-10：分位 17%，盈利率 3.16%）→ **以分位为准**，并提示"两法冲突时降低仓位"。理由是成长指数 PE 天然高，盈利率法会把它一路判成卖出。
- **反向警示**：盈利率说"持有"、分位却在 30% 以下时，工具不会静默通过，而会指出"这类高 ROE、低分红行业盈利率天然偏低，盈利收益率法结构性不适配，要按分位判断请把 `type` 改成 `grow`"。典型就是消费、医药、白酒——它们的盈利率常年 3%~5%，在盈利收益率法下**永远等不到 10% 的买入线**，硬等就会一辈子空仓。工具做的是把这件事说破，而不是替用户偷偷改成买入。

**④ 金额**（两个约束都会真正生效，不是摆设）：

- **单只建议金额**：买入区按"越低估投越多"，量纲随方法走——
  - 盈利率法：`基准 × (当前盈利收益率 ÷ 买入线)^n`
  - 分位法（博格/PB）：`基准 × (买入分位 ÷ 当前分位)^n`
  两式不能混用：分位法的品种盈利率只有 3%，若拿它比 10% 的买入线，会把一只处于历史 17% 分位的成长指数算成"只该投三成"。
- **组合层分配**：每只的实际上限 = `min(单只上限 --max-single, 该只本期建议金额)`，再按 `target` 权重做水位填充；封顶后余量继续给没封顶的，全部封顶则余量明确留债基/货基并说明原因（"不为了花完预算而超配"）。

> 这一条是修过的 bug：早期版本组合层只按 `target` 权重分预算，"减半"和"越低估投越多"算出来的金额根本没被用上（实测中证红利该投 548 元、实际给了 800）。现在上限取两者较小值，两条规则才真正同时生效。

**⑤ 港股口径**：默认沿用书里的 9 折粗口径（对所有盈利打折）。但分红税只作用于分红，精确式是 `盈利率 = 100/PE − 股息率×税率`。用 `--hk-exact` 切换——2026-10 实测恒生国企粗口径 9.62%（持有）、精确口径 10.06%（**跨过买入线**），0.44pct 的差别正好卡在阈值上。所以港股结论必须跑两遍再定。

## 五、"预测"的准确含义：三情景条件推算

工具不给点位、不给涨跌概率。它给的是**"如果估值这样走，年化大约多少"**：

```
假设：股息率不变、盈利按 g 增长
   g = ROE × 留存率 = ROE × (1 − 股息率 ÷ 盈利收益率)
   （也可 --growth 5 手动指定，默认年限 3 年）

情景一 估值不变     = 股息率 + g
情景二 估值回落到买入线 = 股息率 + [(买入线PE ÷ 当前PE)^(1/年限) − 1] + g   ← 只对 value 显示
情景三 估值再跌 30%   = 股息率 + [0.7^(1/年限) − 1] + g
```

三个数应当这样读：

- **情景一是"什么都不发生"的基准**，也是三档里最该被信任的一个——它只依赖分红和 ROE，不依赖市场情绪。
- **情景二是"便宜到能买"的价格对应多少收益**。它在 value 指数上通常比情景一高，说明"等更便宜"是有回报的；但如果它比情景一**低**，说明当前估值已经低于买入线，再等是负回报。
- **情景三是下限**，用来回答"最坏情况我扛不扛得住"。年限越长，这一档越接近纯股息率，因为 30% 的跌幅被时间摊薄了。

成长/周期指数只给情景一与情景三：分位与 PE 不是线性关系，"回落到某个 PE"对它们没有定义，硬算出来的数字比不算更糟。

## 六、日报怎么读

`reports/<日期>.md` 五节：

1. **今日信号**：代码 / 方法 / PE / 分位 / 股息率 / 盈利收益率 / 动作 / 三档推算
2. **变化与提醒**：只在与上次快照比较后真有跨线时出现（PE 变动 ≥3%、分位越过 30%/70%）
3. **资金分配**：预算怎么分、谁触及单只上限、多少留作债基
4. **判断依据**：每只的原文理由 + 增长假设来源 + 最近 7 次 PE
5. **数据与方法声明**：来源、口径、未计入的费用与税

第 2 节是每天唯一需要真的看一眼的地方。**没有变化的日子，正确动作是"什么都不做"**，而不是"找点事做"。

## 七、调度：让它自己跑

Windows 计划任务（每天 15:05，收盘后）：

```powershell
schtasks /create /tn "指数基金每日跟踪" /sc daily /st 15:05 /tr ^
  "python C:\...\skills\index-fund-guide\scripts\tracker.py collect --dir C:\...\fund-track"
```

再挂一条 `report`。也可以把 `analyze` 的输出重定向到一个固定文件，每天只看 diff。

注意两点：

- **收盘后跑**（15:00 之后）。盘中跑会拿到未定的估值与点位，同一天跑三次得到三个 PE。
- 数据源没有 SLA。抓失败时 `collect` 会逐只报错并以非零码退出，别把失败当"没有变化"。

## 八、已知边界

| 边界 | 说明 |
|---|---|
| 分位来自供应商 | 蛋卷的 `pe_percentile` 是它自己算的历史分位；自己攒的快照要到 60 个交易日以后才有参考价值 |
| 只有 8 个指数有接口 | 蛋卷覆盖主流宽基与部分行业；冷门指数会抓不到，需手工补录（`--date` + 直接改 CSV） |
| 估值不是净值 | 跟踪的是**指数**估值，不是基金净值；同一指数的不同基金净值差异不影响判断 |
| 不含费用与税 | 分红税、赎回费、港股通折价、换汇成本都不在推算里，实际收益比推算低 0.3~1.5pct |
| 不预测未来 | 三情景是条件的，不是日历的；"3 年后"只是把估值变化摊到 3 年，不代表第 3 年会怎样 |
| 卖出侧阈值可能失效 | 低利率下卖出线 3.0% 几乎不触发，**卖出主要看分位 >70%**，工具已在报告里标注 |

## 九、和其他脚本怎么配合

```
rawdata.py  → 怀疑供应商算错时，用成分股自己复算 PE/PB，对账
valuation.py→ 只看单只、只看一次时用它；tracker 是它的批量化+时间序列版
dingtou.py  → 跟踪器说"该买多少"，dingtou.py 记"实际买了多少"，report 出真实年化
selftest.py → 改了任何一个脚本，先跑它
```

闭环是：**tracker 决定动作 → dingtou 记录执行 → dingtou report 出真实年化 → 回到 tracker 调整**。缺了记录这一步，跟踪就只是每天看热闹。

## 十、判据分层：哪一条来自书、哪一条来自今天的数

跟踪器的判断是四层叠起来的，混在一起看就会把"书的观点"误当成"今天的结论"：

| 层 | 来源 | 是否随数据变 | 改动成本 |
|---|---|---|---|
| **分类**：这只指数是 value / grow / cycle / skip | 书第 3 章对品种的描述（+ 用户可覆盖） | **不随数据变** | 推翻它要重新读品种档案，不是看今天 PE |
| **方法**：四类 → 四种算法 | 书第 4 章表 4.2 | 不随数据变 | 按类型自动映射 |
| **阈值**：买入线 10% / 卖出线 3% | 当期校准（10Y 国债 1.65%、债基 3.0%） | 随利率变，12 个月或 ±50bp 重算 | 改 `CAL_*` 常量 |
| **数据**：PE / 分位 / 股息率 / 点位 | 本地当天抓取 | **每天变** | 每天 `collect` |

`analyze` 每次都会打印这一层，`init` 会打印每个品种的 `type` 依据（"书第 3 章把它归为 XX 型"），并明确写「这是描述性分类，不是对当期估值的判断」。这句话是防污染的闸门：**chapter 3 只决定"用哪把尺子"，chapter 4 才决定"量出来是几"**。

三条自查：

- 把 `type` 当成"当期数据结论"去用 → 错。中证红利是 value，与它今天便不便宜无关。
- 因为"书里说它高股息"就认定它该买 → 错。高股息是品种属性，买不买看分位与盈利率。
- 因为"书里说创业板波动大"就跳过它 → 错。它可能正好在历史最低分位（2026-10 就是 17%）。

## 十一、时间纪律：数据日、抓取时间、盘中/收盘

三个时间必须分开看，`analyze` 表头会同时给出：

| 时间 | 含义 | 不对时的后果 |
|---|---|---|
| **数据日** | 这张快照代表哪一天 | 旧数据出信号 = 用上周的价格做今天的决定（`--max-age` 超限会红字提醒） |
| **抓取时间** | 本地几点几分抓的 | 15:00 前抓 = **盘中值**，同一天跑三次会有三个 PE（实测 10.82→10.88→10.89） |
| **报告期**（`rawdata.py`） | 财报截止到哪一季 | 用了未披露完的报告期 → Σ净利润偏小 → PE 被高估 |

抓到盘中数据时，`collect` 与 `analyze` 都会提示「收盘后重跑一次，覆盖同一天」。同一交易日重复 `collect` 是**覆盖**而不是追加，所以盘中抓完、收盘再抓，最后留下的是收盘口径。
